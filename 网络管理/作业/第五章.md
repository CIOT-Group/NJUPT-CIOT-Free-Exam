### 1. 为什么需要RMON？网络监视器能提供哪些管理信息？
RMON是为了弥补SNMP在远程网络监控方面的不足。它能提供更详细的网络流量分析和历史数据记录，减少对网络管理站的依赖。
网络监视器可以提供的信息包括：

- 流量统计（如每端口的带宽使用率）
- 错误率
- 网络利用率
- 主机列表及其活动
- 对话信息（通信对之间的流量）
- 报警和事件信息等

### 2. RMON对表对象的管理做出了什么改进？

RMON引入了对历史数据的记录机制，增强了表对象（如流量表、主机表、对话表等）的管理能力。它采用Ring Buffer结构，支持离线分析；同时支持事件驱动方式，提高了监控的实时性与效率。

### 4. 试分别写出产生上升、下降报警的规则。

- 上升报警规则：当被监控变量的值从低于阈值上升至等于或高于阈值时，产生上升报警。
- 下降报警规则：当被监控变量的值从高于阈值下降至等于或低于阈值时，产生下降报警。

### 6. 试描述报警组、过滤组、事件组和包捕获组的关系。

- 报警组：定义要监控的对象及阈值，检测到异常时生成事件。
- 事件组：定义发生事件后要采取的动作（记录日志、发送trap）。
- 过滤组：对捕获的数据包进行筛选，决定是否捕获该包。
- 包捕获组：根据过滤规则对数据包进行捕获并存储，供管理站分析使用。

它们之间的关系是：报警组产生事件 → 触发事件组响应动作；过滤组配合包捕获组实现数据筛选与捕获。

### 7. RMON2扩充了哪些功能组，它们的作用是什么？

RMON2在原有RMON1基础上增加了对网络层和应用层的支持，扩展的功能组包括：

- Protocol Directory Group：列出支持的协议。
- Protocol Distribution Group：统计各协议占用的带宽比例。
- Address Map Group：映射网络层和链路层地址。
- Network Layer Host/Matrix Groups：提供基于网络层的主机/对话统计。
- Application Layer Host/Matrix Groups：提供基于应用层的主机/对话统计。
- User History Group：用户自定义的历史统计数据组。

这些功能有助于从更高层次分析网络性能和故障。

### 8. 为什么要使用外部对象作为表的索引？

使用外部对象作为索引，可以避免数据冗余，实现多个表间的关联和统一管理，便于扩展和数据一致性维护。

### 9. RMON2如何标识协议之间的关系？

通过Protocol Directory Group中的协议树结构，RMON2能建立各协议间的层次关系，如TCP/IP协议族中，IP在下，TCP在上，HTTP在TCP之上。这样可清晰标识协议栈中的隶属关系，便于进行多层次的统计分析。
